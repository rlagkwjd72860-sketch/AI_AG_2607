# 조사 보고서(docx) 생성

주제 하나만 주어져도, 실제 웹 검색으로 최신 자료를 모으고 정해진 서식의 Word 보고서로
정리해 저장하는 것이 이 스킬의 목적이다. "무엇을 조사할지"는 대화 맥락에서 파악하고,
"어떻게 보고서를 만들지"는 아래 워크플로우와 고정 템플릿을 그대로 따른다 — 매번 서식을
새로 고민할 필요가 없게 하기 위함이다.

## 왜 스크립트로 만드는가

python-docx로 문서를 짤 때 제목 크기, 한글 폰트(맑은 고딕) 적용, 표 헤더 배경색 같은
서식 코드는 매번 실수하기 쉬운 부분(특히 한글 폰트는 `eastAsia` 속성을 별도로 안 주면
Word에서 반영되지 않는다)이라 `scripts/build_report.py`에 고정해뒀다. Claude가 할 일은
**리서치와 글쓰기**이고, 서식은 스크립트에 맡긴다.

## 워크플로우

1. **주제/범위 확정**: 사용자가 준 주제가 너무 넓거나(예: "AI 조사해줘") 모호하면, 조사
   범위(글로벌/국내, 시장 관점/기술 관점 등)를 한 줄로 확인하거나 합리적으로 좁혀서 진행하고
   어떻게 해석했는지 결과에 짧게 밝힌다. 이미 구체적이면(예: "에코백 시장 트렌드") 바로 진행한다.

2. **웹 리서치**: `WebSearch`로 최신 뉴스·산업 리포트·시장조사 자료를 여러 각도(시장 규모/트렌드,
   경쟁사·브랜드 사례, 이슈·논쟁, 규제 동향 등)에서 검색하고, 근거로 쓸 만한 페이지는
   `WebFetch`로 열어 구체적 수치·사실을 확인한다. **모든 핵심 수치·주장에는 출처가 있어야 한다** —
   출처 없는 수치를 만들어내지 않는다. 검색한 URL은 전부 기록해뒀다가 참고자료 섹션에 쓴다.

3. **내용을 콘텐츠 JSON으로 정리**: 아래 "문서 구조(고정 템플릿)"에 맞춰 섹션을 구성하고,
   `references/content_schema.md`에 정의된 JSON 스키마 형태로 리서치 내용을 작성해 임시 파일로
   저장한다(예: 스크래치패드에 `content.json`). 이 JSON이 곧 보고서의 실제 콘텐츠이므로, 문장은
   보고서에 그대로 실릴 완성된 한국어 문장으로 쓴다.

4. **스크립트 실행**으로 docx를 생성한다. 긴 콘텐츠 JSON은 손으로 쓰다 보면 괄호/쉼표가
   어긋나기 쉬우니, 실행 전에 `python -m json.tool <content.json>`으로 JSON 문법부터
   확인해두면 스크립트 실패로 왕복하는 시간을 아낄 수 있다:
   ```
   python -m json.tool <content.json> > /dev/null
   python .claude/skills/docx-research-report/scripts/build_report.py --input <content.json> --output <output.docx>
   ```
   메인 컬러는 사용자가 특정 색을 언급했으면 `--color`로 지정하고, 언급이 없으면 JSON의
   `main_color` 기본값(또는 스크립트 기본값)을 그대로 둔다.

5. **저장 위치/파일명**: 프로젝트에 `research/` 폴더가 있으면 그 아래에 저장한다(없으면 새로
   만든다). 파일명은 `{주제}_조사보고서.docx` 패턴을 따른다 (예: `에코백_시장조사_보고서.docx`).
   사용자가 다른 위치/이름을 요청하면 그에 따른다.

6. **결과 보고**: 생성된 파일 경로와 함께, 몇 개 섹션으로 구성했는지·주요 출처 개수를 1~2문장으로
   요약해 알려준다.

## 문서 구조 (고정 템플릿)

특별한 요청이 없으면 아래 8단 구조를 기본으로 쓴다. 주제 성격에 안 맞는 섹션(예: 브랜드 사례가
의미 없는 주제)은 빼거나 이름을 바꿔도 되지만, "표지-목차-본문-참고자료"라는 전체 골격과
서식(제목/본문 크기, 폰트)은 항상 유지한다.

1. 조사 개요 — 보고서 목적 1~2문장
2. 조사 방법 및 범위 — 조사 방법(웹 공개자료 등), 범위, 대상을 짧게
3. (주제) 현황 — 시장 규모, 현재 상태 등 정량적 배경
4. 주요 트렌드/동향 — 하위 섹션(4.1, 4.2, ...)으로 세분화
5. 쟁점 사항 — 논쟁거리, 반대 의견, 한계점 (있는 경우)
6. 사례 — 대표 기업/브랜드/제품 사례
7. 결론 및 시사점
8. 참고 자료(출처) — 검색으로 확인한 URL 전부

표지에는 제목/부제/작성일/작성자("춘식이 (AI 조사 지원)")/문서 구분을 넣는다. 오늘 날짜는
시스템 컨텍스트의 현재 날짜를 사용한다.

## 콘텐츠 JSON 스키마

전체 필드 설명과 예시는 `references/content_schema.md`를 읽고 따른다. 핵심만 요약하면:

- `sections`: 배열. 각 섹션은 `title`(번호 직접 포함, 예: `"1. 조사 개요"`), `blocks`
  (`paragraph`/`bullets`/`table` 타입), 선택적 `subsections`(같은 구조)를 가짐
- `references`: `{"text": "...", "url": "..."}` 배열. 목차는 섹션 제목에서 자동 생성되므로
  따로 만들 필요 없음
- 번호는 스크립트가 자동으로 매기지 않는다 — `title`에 직접 포함시켜야 목차와 본문 제목이
  항상 일치한다

## 유의 사항

- 리서치 없이 지어낸 통계나 사례를 넣지 않는다. 확인 안 된 수치는 "정확한 수치 확인 어려움"처럼
  범위로 표현하거나 아예 뺀다.
- 참고자료 URL은 실제로 검색/열람한 페이지만 넣는다(추측으로 URL을 만들지 않는다).
- 표(`table` 블록)는 수치를 비교해서 보여줄 때만 쓰고, 억지로 모든 섹션에 넣지 않는다.
